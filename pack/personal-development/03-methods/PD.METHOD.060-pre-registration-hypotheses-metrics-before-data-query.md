# PD.METHOD.060 — пре-регистрация гипотез и метрик до запроса к данным

## Суть метода

Файл с гипотезами и метриками, по которым будет оцениваться результат, фиксируется коммитом ДО первого запроса к данным (например, к базе показателей), как требует дисциплина доказательности. Всё, что обнаруживается сверх заранее заявленного списка, попадает в отчёт с явной пометкой «разведочное» (exploratory), а не выдаётся за предсказанный результат.

## Обоснование

Без пре-регистрации легко подогнать формулировку гипотезы под уже увиденный результат (post-hoc rationalization), что делает «подтверждение» гипотезы малозначащим. Явная временная метка коммита до запроса к данным и явная маркировка неожиданных находок сохраняют эпистемическую честность анализа.

## Применение

Любой анализ личных данных/показателей, где формулируется гипотеза до просмотра результата (не чисто описательная статистика).

## Специализация: доказательность роста через карточку кейса и гейт ступени (WP-587)

Для оценки эффекта вмешательства на малой выборке (n≤20) пре-регистрация операционализируется так:

- **Блок «А» (замораживается ДО контрольного замера):** наблюдаемая формулировка ограничения, ожидаемый признак и порог без свободного текста (`метрика_тип: шкала|якорь`), окно и протокол контроля, контргипотеза, неизменяемый след времени; регламент «24 часа» на дозаполнение; отметка «почему главное» и окно проверки устойчивости (см. ниже).
- **Блок «Б» (после):** две раздельные точки оценки — участник дословно + наставник, без переписывания.
- **Единица хранения — карточка кейса**, не плоская таблица (таблица теряет даты, цитаты, историю версий; таблица генерируется из карточек, не наоборот).
- **Метка «один_источник» = карантин**, не «почти подтверждено» — публикация ждёт второго независимого источника.
- **Граница с гейтом ступени:** пометка «в досье» ставится только после решения по ступени; журнал из девяти полей с механической проверкой «время пометки позже времени решения» (слепой режим оценки рассмотрен и отвергнут как нереалистичный при n≤20).

Универсально для любой оценки эффекта вмешательства на малой выборке, не только для роста ступени.

### Тест главного ограничения и отложенная проверка устойчивости (дополнение 2026-10-02, РП-170)

Для записи «ограничение / что сделали / было-стало» формат записи ведущего потоков С1/С2 (РП385, РП587) с 23.09.2026 добавляет два шага. Без них запись остаётся «было-стало» без проверки: не установлено, что вмешательство било по настоящему узкому месту, и не проверено, что эффект не откатился.

- **Тест главного ограничения (в Блоке «А»).** Перед записью ограничения проверить вслух с участником: «это правда то, что тормозит сильнее всего прямо сейчас, а не просто одна из помех». Иначе запись случайная, не показательная. Результат проверки — отметка «почему главное» в Блоке «А».
- **Окно проверки устойчивости (в Блоке «А»).** Через 2-4 недели участнику задаётся один вопрос: «то, что мы тогда поправили, — всё ещё держится?». Ответ (да / нет / частично) дописывается к исходной записи кейса тем же наставником. Без этого шага кейс не годится для досье, только «было-стало» без проверки на откат.

Применения метода в этой части пока нет: формат внесён в запись ведущего 23.09.2026.
