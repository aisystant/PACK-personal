# PD.METHOD.062 — Трёхуровневая структура минимального набора методов по типу триггера пересмотра

## Суть метода

При проверке набора методов/практик на минимальность каждый элемент классифицируется по ТИПУ его триггера пересмотра, не по интуитивному чувству «нужности»: **Уровень 1 — самоподдерживающееся ядро.** Методы с собственным decision-bearing триггером, не календарным ритуалом «раз в месяц посмотреть» (обнаруженная ошибка, sunk-cost сигнал, нарушение границы agency). **Уровень 2 — несущий слой.** Даёт отдельный содержательный вклад (вход/выход/stop-condition), но триггер пересмотра приходит ОТ уровня 1, не свой собственный. **Уровень 3 — базовая предпосылка.** Засчитывается в контур только при явном триггере; без него — фоновая гигиена без обратной связи, не часть контура. Таксономия типов триггеров используется как чек-лист покрытия: для каждого класса жизненных ситуаций проверяется, какой уровень на него отвечает и отвечает ли вообще.

## Обоснование

Интуитивный «стартовый набор» (просто перечисление нескольких ID без критерия) не может быть проверен на минимальность или самоподдержание — непонятно, какой элемент необходим и какой пробел в покрытии остался незамеченным. Классификация по типу триггера даёт проверяемый критерий: элемент без собственного и без наследуемого триггера пересмотра — не часть минимального самоподдерживающегося набора; а применение таксономии как чек-листа вскрывает пробелы, которые перечисление не видит.

## Аудит существующего каталога (две проверки на метод)

Для каждого метода каталога явно проверяется:
1. Есть ли у него собственный decision-bearing триггер, или триггер наследуется от метода уровня 1.
2. Входит ли метод в контур непрерывно или только по пороговому условию.

## Применение

Проверка любого каталога методов/практик на минимальность и самоподдержание — не только личных методов: оценка набора эксплуатационных правил, набора ежедневных ритуалов агента, минимального набора guard'ов конвейера.
